Target: `runner/` of this project (Zulfi Portal + ZakaaDash), upgraded **in place**.

## Owner decisions (2026-11-07)

| # | Question | Decision |
|---|----------|----------|
| D1 | Rebuild strictly vs upgrade | **Upgrade in place**: implement the full spec and keep the Zulfi extras (presets, phase-gate helper, pace / browser / Grid, CLI report-history index). Old run history stays readable. |
| D2 | Spec stores encrypted passwords in `test_data` and passes logins as `-D` | **AGENTS.md wins**: credentials reach the JVM only as child environment variables and the runner never saves a password. ## Adaptations required by this project (spec text → implementation)

| Spec | Here | Why |
|------|------|-----|
| NAWAH systems (pms, strategy, …), `com.nawahtech.*` | `zulfi`, `zakaadash`, `com.taf.systems.*` | Two systems in this TAF (`tools/systems.py`). |
| Logins as `-D` keys (`data.pms.login-data…`) | Logins as env vars (`ZULFI_USER`/`ZULFI_PASSWORD`, `ZAKAADASH_EMAIL`/`ZAKAADASH_PASSWORD`) | D2 / AGENTS.md. |
| Preflight via `com.nawahtech.tools.Preflight` (API login) | URL reachability (+ Selenium Grid `/status`); authentication reported as *not verified* | Neither system exposes an API sign-in contract (existing PF test contract). |
| Progress line `Test Case <name> (passed\|failed\|skipped)` | Both that line and the framework's `[TAF-PROGRESS] START\|PASS\|FAIL\|SKIP class#method` are parsed | Framework already emits `[TAF-PROGRESS]`. |
| "Retry timing failures once" (framework side not described) | New core `com.taf.core.listeners.TimingRetry` (TestNG retry analyzer + annotation transformer), added with `-listener` only when the run's *retry* switch is on | No retry analyzer existed. It never retries assertions, and never retries anything in a run where a create/submit gate (`*.create.enabled`, `*.submit.enabled`, `*.lifecycle.enabled`) is `true` — keeps the AGENTS.md "at most one creating submit / no automatic retries" rule. |
| "Bug check" = soft assertion of a known bug | `soft = true` when the Allure result links an issue (`@Issue`) or carries label `bugCheck` | Same meaning as `tools/regression.py` (classes with `@Issue` are known-bug checks). |
| `-DDEFAULT_WAIT=25` when parallel | Same key (`waits.properties`), plus `-Dzakaadash.explicit.wait=25` | Both systems' wait keys. |
| Parallel classes 1–4 | `maxThreads`: Zulfi 4, ZakaaDash **1** | AGENTS.md: ZakaaDash suites stay serial (shared account). Zulfi analysis package is a `serialGroup` (fixture manifest order). |
| Allure HTML generated by the framework (`output/reports/AllureReport_*.html`) | Use `output/reports/latest/allure-html/index.html` (Zulfi publisher) or `AllureReport_*.html`, else generate with the Allure CLI; copied to `runs/<id>/report.html` | Zulfi's `RunReportPublisher` writes `allure-html/index.html`. |
| Claude worktrees (git) | Copy of the project (sources, suites, tools, docs; never `config/credentials.local.properties`, `target/`, reports) in `RUNNER_AGENT_WORK` with its own throw-away git baseline → real `git diff`, merge with backup + undo | This folder is not a git repository. |
| GitHub update default `InnovaDigitsTeam/NAWAH_Automation` | No default: disabled until `RUNNER_GITHUB_REPO` is set | Updating from the NAWAH repo would overwrite this project. |
| `take_over()` kills the existing runner | Kills it only when it has no active run (or with `--force`) | A take-over would otherwise kill live test runs silently. |
| Systems page editable only with MySQL | Editable with both stores (FileStore keeps it in `runner/config-store.json`, git-ignored) | Local use has no MySQL. Seeds (`environments.json`, `modules.json`) are never written. |
| Basic auth only | Basic auth (when `RUNNER_PASSWORD` is set) **plus** the existing Host allow-list and `X-Runner` header on every POST | Keeps the current DNS-rebinding / CSRF protection. |
| Run object has `preflight` twice (flag and result) | `preflight` = flag, `preflightResult` = `{ok, lines, checks}` | One key cannot hold both. |

Defects found and fixed during verification:

* Runner JVMs missed `-Djdk.net.unixdomain.tmpdir` (surefire argLine only) → Chrome failed with "Unable to establish
  loopback connection"; the runner now passes it (`runner/.tmp`).
* Failed `@BeforeMethod` fixtures were counted as broken tests → reported apart as setup failures.
* POSTs refused before the body was read (403/401/404) could reset the connection on Windows → bodies are always read.
* Read-only Claude copies could survive (git read-only files on Windows) → robust removal before the status changes.
* Severity could not be cleared back to Unrated → fixed; framework `failureCategory` now wins over message patterns.
